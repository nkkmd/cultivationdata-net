# ポートフォリオ・モンテカルロ・シミュレーター

過去の金融資産の価格データを基に、ポートフォリオの将来残高をモンテカルロ・シミュレーションするPythonスクリプトです。**農業経営支援基金**のように、長期運用を続けながら定期的に資金を支出する場合も分析できます。

大学基金の運営思想に倣い、「基金の最終残高」だけでなく「計画した支出を継続できるか」を評価するため、**取り崩し方式・支出頻度・最低残高**を設定できます。取り崩しを行わない従来型の試算も可能です。

## 特徴

- `yfinance`で、株式分割・配当を調整した過去の終値を取得します。
- 複数銘柄の価格変動の**相関**を考慮し、日次対数リターンの平均・共分散から将来経路を生成します。
- 期間（月）、試行回数、乱数シード、目標資産配分、リバランス間隔を指定できます。
- 取り崩しを**月次（毎月末）**または**年次（12か月ごとの月末）**に設定できます。
- 最終基金残高、実際に支払えた累計額、予定支出の不足確率を確認できます。
- 基金残高と累計支出額の推移をPNG画像として保存し、対応する環境では画面にも表示します。

## 動作環境

- Python 3.9以上を推奨
- `numpy`、`pandas`、`yfinance`、`matplotlib`

```bash
python -m pip install numpy pandas yfinance matplotlib
```

以前のコードで利用していた`scipy`は今回の実装では不要です。

## 使用方法

```bash
python monte_carlo_simulator.py
```

画面の案内に従って、次を指定します。

1. **銘柄と目標配分**：ティッカーシンボルと0～1の比率（例：`0.6`と`0.4`）。合計が100%になるまで入力します。
2. **過去データの期間**：開始日・終了日（`YYYY-MM-DD`、終了日は含まない）。銘柄に共通する有効な価格が最低61営業日分必要です。
3. **基金の初期金額**：各銘柄の価格と同じ通貨建ての金額（例：`30000000`）。
4. **将来のシミュレーション期間**：月数（例：`360`で30年）。
5. **試行回数**：空欄なら`1000`。
6. **リバランス間隔**：月数（例：`12`で年1回）。`0`ならリバランスしません。
7. **取り崩し方式とその条件**：下表を参照してください。`0`なら取り崩しなし。
8. **乱数シード**：数値を指定すると同じデータ・設定・環境で結果を再現しやすくなります（例：`42`）。空欄なら毎回新しい乱数を利用します。

### 取り崩し方式

| 入力 | 方式 | 支出額の計算方法 |
|---|---|---|
| `0` | 取り崩しなし | 支出を行わない |
| `1` | 定額 | 年間予定額 ×（支出間隔の月数÷12）。指定した年率で名目額を増減可能 |
| `2` | 評価額定率 | 当該支出月の取り崩し前残高 × 年間支出率 ×（支出間隔の月数÷12） |
| `3` | 平準化定率 | 直近12か月の**取り崩し前月末評価額**の平均 × 年間支出率 ×（支出間隔の月数÷12） |

- **支出頻度**：`1`は毎月末、`12`は12か月ごとの月末。初回支出はそれぞれ1か月目、12か月目です。中間の月は支出しません。
- **年間支出率**：`3`と入力した場合は年率3%（プログラム内部では`0.03`）。月次支出なら各月の参照残高の`0.03 / 12`を予定額とします。
- **定額方式のインフレ調整**：`2`と入力した場合は年間2%の増額設定。初回の支出額を起点に、毎月なら支出ごとに年率相当分、毎年なら1年ごとに増額します。これは**予定支出の名目増額**であり、基金全体の実質価値や実際の物価を予測するものではありません。
- **平準化定率**：直近12か月の取り崩し前評価額を利用します。開始直後は過去12か月分の試算値がないため、初期残高を含む利用可能な観測値だけで平均します。大学基金の支出ルールの**簡易モデル**であり、特定の大学の制度を再現するものではありません。
- **最低残高**：各回の取り崩しによって残高が指定額を下回らないよう、支払可能額を制限します。**市場下落そのものによる最低残高割れは防止しません。**

すべての方式で、資金不足時は**借入を行わず、基金残高をマイナスにせず、支払える範囲だけを取り崩し**ます。支出予定額との差額を「支出不足額」として記録します。以後の支出についても同じ条件を適用します。

### 入力例：基金から年間3%を支出

初期額を`30000000`、シミュレーション期間を`360`、試行回数を`1000`、リバランス間隔を`12`とし、取り崩し方式を`3`（平準化定率）、頻度を`12`、年間支出率を`3`、最低残高を`0`とします。

初期残高が3,000万円で年率3%なら、**単純計算では年90万円**が目安ですが、実際の取り崩し予定額は各年の平準化評価額によって変動します。したがって毎年90万円の支出を保証する設定ではありません。

年90万円の**名目定額支出**を調べたい場合は、方式を`1`、年間予定額を`900000`、インフレ調整を`0`としてください。両者を比較することで、固定的な支出の安定性と基金残高維持の両立について検討できます。

## 出力の読み方

実行後、以下の指標を表示します（金額はすべて入力した基金の通貨単位です）。

| 指標 | 意味 |
|---|---|
| 最終残高の平均・中央値・最小・最大 | 指定した期間の最終月末、**取り崩し後**の基金残高 |
| 最終残高の90%予測区間 | シミュレーションの終期残高の5パーセンタイル～95パーセンタイル。統計的な推定値の「信頼区間」ではありません |
| 終期残高の95% VaR・CVaR | 終期残高が初期金額からどの程度下がるかを基準にした値。**取り崩しも残高減少に含まれるため、純粋な運用損失のVaRではありません** |
| 実際に支払えた累計額の中央値 | 計画どおりか不足時に減額されたかを含む累計支出 |
| 予定支出の不足が一度でも発生する割合 | 少なくとも1回、予定額を全額支払えなかった試行数の割合。基金がゼロにならなくても起こり得ます |
| 不足額累計の平均値 | 全試行の未払い予定額合計の平均 |

グラフは**各月末の基金残高**と**基金からの累計支払額**を別々に表示します。それぞれ試行の中央値、5～95パーセンタイル帯（基金残高のみ最大100本の個別経路も表示）を示します。

### グラフの保存と画面表示

実行時には、**実行した作業ディレクトリ**（`python`コマンドを実行した場所）に次のPNGファイルを保存します。

- `monte_carlo_fund_balance.png` — 取り崩し後の基金残高
- `monte_carlo_cumulative_withdrawals.png` — 基金からの累計支出額

画面表示に対応したMatplotlibバックエンドでは、画像を保存したうえでグラフを表示します。`Agg`などの**非対話型バックエンド**（画面のないサーバー、CI、一部のWSL・リモート実行環境など）では、`plt.show()`を呼ばずにPNG保存のみ行います。保存先の絶対パスは実行時に表示されます。

```bash
# GUIを使わず画像として保存する例（Linux / WSL）
MPLBACKEND=Agg python monte_carlo_simulator.py
```

同名のPNGファイルがある場合は上書きされます。関数から利用する場合は、`plot_results(result, portfolio, output_dir="出力先フォルダー")`で保存先を変更できます。画面に表示したい場合は、利用環境に対話型GUIバックエンドが必要です。

### 分析すると有用な比較

- 同じ投資条件で、**取り崩しなし／年3%定率／年90万円定額**を比較する。
- 月次支出と年次支出で、支出不足の頻度や基金残高がどう変わるかを比較する。
- リバランスなしと年1回のリバランスを比較する。
- 取り崩し後に保護する最低残高の設定により、実際の支出額がどの程度制約されるかを確認する。

比較実験では乱数シード・対象銘柄・データ期間・試行回数を揃えます。シードを揃えても、結果の差が必ず統計的に有意になるわけではありません。

## モデルと計算上の前提

1. 過去の**調整後終値**から、銘柄別の日次対数リターンの標本平均と共分散を推定します。`yfinance.download(..., auto_adjust=True)`を指定し、`Close`を使用します。ティッカー1件でも複数件でも対応します。
2. 推定した平均・共分散を持つ**多変量正規分布**から、日次対数リターンを独立に発生させます（幾何ブラウン運動型の近似）。銘柄間の相関は残りますが、日をまたぐ相関や市場の構造変化は再現しません。
3. **1か月は21営業日、1年は252営業日**と固定します。各月の21営業日分を先に運用し、月末に資産を評価して、取り崩し→必要ならリバランスの順に処理します。
4. 支出は各資産からその時点の保有割合に応じて比例売却し、リバランス月は残高を目標配分に戻します。取引可能額・売買単位は無制限と仮定します。
5. **追加の積立・寄付・借入・現金利息・税金・売買手数料・運用管理費・為替換算・実質額換算は実装していません。** 現金の別勘定や農業経営からの支援要請も対象外です。
6. 複数の通貨で取引される資産を為替換算せずに混ぜることはできません。**すべての資産価格・初期金額・支出予定額を同一通貨で揃えてください。**
7. 過去データの欠損がある日付は、**全銘柄に共通する有効日**だけを採用します。銘柄ごとに履歴期間が大幅に異なる場合、標本が偏る可能性があります。

**注意：** 正規分布では暴落・急回復・ボラティリティの急拡大などの「テールリスク」を過小評価する可能性があります。支出不足確率は**このモデルと入力条件の下での試算値**であり、将来の実際の不足確率ではありません。将来的には収益率の不確実性、インフレ、実質支出額、長期市場低迷、農業所得との同時悪化などを考慮する拡張が考えられます。

## 既存版との変更点

- 旧版の`rebalance_months`は、ポートフォリオ全体を1つの収益率で処理していたため、**リバランスしてもしなくても同じ計算**でした。新版では銘柄別の価格推移と残高を試算し、指定月に実際の再配分を反映します。
- シミュレーションは**日次の累積リターン比率**ではなく、**月次の取り崩し後の基金残高**を保存・表示します。`monte_carlo_simulation`の引数と戻り値も変更しています。以前のコードから関数を直接呼び出している場合は更新してください。
- yfinanceの現行仕様に対応するため、`auto_adjust=True`で取得する`Close`列を明示的に利用します（古い`Adj Close`列には依存しません）。
- 旧版の「90%信頼区間」は、5～95パーセンタイルの**予測区間**として正確に表記しました。

## 検証

Python標準ライブラリ`unittest`を使ったオフラインの単体テストは、同梱の`test_monte_carlo_simulator.py`で実行できます。

```bash
python -m unittest -v test_monte_carlo_simulator.py
```

テストでは、一定リターン下の定額支出、資金不足時の支払い制限、定率・平準化定率、再配分、乱数再現性などを確認します。**実際の価格取得にはネットワークが必要です**。株価データ提供側の制限・欠損・仕様変更によって取得できない場合があります。
